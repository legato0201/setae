# SETAE アプリ品質改善 / 第2段階・v1.0.250

作成日: 2026-08-28  
状態: ローカルの実装完了・配布候補。本番には未適用。性能基準の未達は検証報告に明記する。

## 今回の範囲

v1.0.249で修正した「個体登録中に背景が遷移する」問題を維持しながら、登録・編集の情報量、下書き案内、大量データの検索表示を改善する。既存の「Natural History Museum × Modern Research Database」の配色、文字、余白、共有部品を継続する。

第2段階の全画面を完了したものではない。今回の単位は個体登録・編集、共通下書き通知、コレクションの段階表示である。

## 個体登録・編集

- 必須の「個体識別」は常時表示する。「現在の状態」「導入・飼育情報」「写真・メモ」「公開・管理」は、必要なときに開く。
- 既定値だけの新規フォームでは任意項目を閉じる。編集時の入力済み項目、数値の0、既存写真があるグループは開く。
- native `details` / `summary` を使い、開閉による入力欄の再生成や無効化を行わない。文字、写真のFile、選択状態、送信項目を保持する。
- 通常の検証、native invalid、APIの項目エラー、エラー要約からの移動では、該当グループを開いてから入力欄へ移動する。
- 下書きの復元前に種の入力方式とDOMを揃える。分類のchangeによって、復元途中の種ID・手入力名が失われることを防ぐ。
- 下書きに種IDだけが残り名称がない場合、名称を推測せず「図鑑の種 #ID」と表示する。種IDを保持し、「変更」から確認・選び直しができる。
- 写真ファイル自体は下書きに保存しない。復元できない写真がある場合、写真グループを開き、再選択の案内を残す。

## 下書き通知

現在入力中の自動保存を「復元できる前回の入力」として再掲しない。適用できる値の差分がある前回の下書きだけ、復元・破棄の操作を示す。入力開始、復元、破棄の後に同じ案内を再掲しない。

個体登録では通知をスクロールする本文に置き、見出しと保存ボタンの領域を圧迫しない。復元は通常のボタンとし、保存の主操作と視覚上の優先度を区別する。下書きキー、保持期限、秘密情報・ファイル本体を保存しない方針、未保存変更の確認は維持する。

## コレクションと検索

PCとスマートフォンで同じ行DOMを使い、幅に応じて配置を変える。選択モードでないときは、見えない選択チェックボックスを生成しない。

大量データでは、検索計算よりもHTML挿入とレイアウトが負荷の中心だった。検索・並び替え・保存ビューは全データに適用し、描画だけを最初の50匹に制限する。「50 / 167匹を表示」のように表示数と総数を示し、「さらに表示」で50匹ずつ追加する。件数を小さく見せたり、検索対象を先頭50匹に限定したりしない。

- 追加表示は既存の行・チェックボックス・検索入力欄を保持する。最後の追加後も件数表示へフォーカスを戻す。
- 全件選択は、まだ追加表示していない個体を含む検索条件への一致集合に適用する。
- 検索語や保存ビューの条件が変われば50匹へ戻す。台帳／写真の切り替え、選択モード、個体詳細から戻る操作では表示上限を保持する。
- 履歴から検索語を復元すると、IME・重複入力判定にも同じ値を反映する。以前に検索した語を再入力しても、入力欄と結果が食い違わないようにする。
- 追加時に現在の行順・件数・表示方式が一致しなければ、通常の再描画で整合性を回復する。
- スマートフォンでは「台帳」「写真」を途中で折り返さず、表示切替と選択チェックの操作幅を44px以上にする。

## 変更しない範囲

API URL、DB構造、権限、認証、既存個体の保存値、本番の図鑑・個体データは変更しない。表示上限はブラウザー内の描画制御であり、APIから取得するデータを欠落させない。

## 検証と残る段階

結果と配布候補はワークスペースの `release-evidence/v1.0.250/` および `release-report-v1.0.250.md` に記録する。既存の性能閾値を緩めずに測定し、失敗した測定も残す。

初期表示の軽量化と、固定性能基準の安定達成は分けて評価する。追加表示ではDOMを保持しても、キャッシュ用のHTMLは表示済み全件分を生成しているため、生成処理の差分化も次に点検する。

引き続き、Quick Record、飼育容器、ベビー群における操作の優先順位・空状態・エラー復帰を同じ基準で点検する。表示幅の変更や合成APIの試験は、実機の日本語IME・ソフトウェアキーボード・写真選択、本番WordPress保存、実ユーザー試験の代替とは扱わない。
