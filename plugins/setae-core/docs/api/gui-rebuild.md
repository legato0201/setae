# GUI再構築仕様

## 目的

機能追加で画面が密集した現状を整理し、利用者が「今日すること」「個体を見る」「記録する」「交流する」を迷わず完了できるGUIへ作り直します。APIと表示を分離し、画面内でWordPress投稿やAjax固有形式を扱いません。

## 画面の情報構造

第一階層は4つに絞ります。

| 画面 | 主目的 | 主なAPI |
|---|---|---|
| 今日 | 今日必要なお世話と直近状況 | `/app/bootstrap`, `/care-summary`, `/my-spiders` |
| 個体 | 通常個体、ベビー群、餌在庫 | `/my-spiders`, `/baby-groups`, `/feeders` |
| 記録 | 個体・QRから素早く記録 | `/spider/{id}/events`, `/qr/*` |
| 交流 | お世話フィード、相談、繁殖募集、図鑑 | `/care-feed`, `/topics`, `/bl-candidates`, `/species` |

プロフィール、通知、外部連携は右上のアカウントメニューへ集約します。繁殖募集は個体詳細で公開設定し、交流の「繁殖募集」から閲覧します。アプリ内契約・申請・DMは設けません。

## 起動フロー

1. `GET /app/bootstrap` を取得する。
2. `authenticated=false` なら公開閲覧と登録導線だけを有効にする。
3. ログイン中は「今日」のために `/care-summary` と `/my-spiders?scope=active` を並列取得する。
4. 他タブのデータは初回表示時に遅延取得する。
5. `401` を受けたら1回だけ `/session` を確認し、ログイン画面へ誘導する。

## 状態管理

| 状態 | 扱い |
|---|---|
| `session` | bootstrap/sessionを正本にする |
| `me` | プロフィール更新後に返る全データで置換 |
| `spiders` | `id` をキーに正規化。作成・更新レスポンスで差分更新 |
| `careSummary` | 記録作成・削除後にレスポンスまたは再取得で更新 |
| `babyGroups` | 一覧は概要、詳細は選択時だけ取得 |
| `feeds/topics` | ページ単位。フィルタ変更時に破棄 |
| `drafts` | 記録・投稿本文は端末へ一時保存 |
| `offlineQueue` | `operation_id` 付きで `/offline/sync` へ送る |

## 操作の設計原則

- 破壊操作は対象名を示して確認し、処理中は二重送信を止める。
- 作成・更新後は全画面再読込せず、APIレスポンスで局所更新する。
- 空状態には、その状態を解消する主操作を1つだけ置く。
- フィルタ、並び順、検索は同じ画面の一箇所へまとめる。
- 「投稿」「保存」「記録」のボタン外観と待機・成功・失敗状態を共通化する。
- APIエラーの `message` を基本表示し、入力欄へ関連付けられる場合は欄の直下へ出す。
- お世話記録の共有は記録保存の追加オプションとし、記録そのものを阻害しない。

## APIクライアント規約

- URLはbootstrapから得たAPI rootを基準にする。
- ログイン操作には常に `X-WP-Nonce` を付ける。
- 画像があるときだけ `FormData`、それ以外はJSONを使う。
- GETはキャンセル可能にし、古い検索結果で新しい表示を上書きしない。
- POSTは二重送信防止キーを画面側で持つ。外部記録とオフライン同期はAPIの冪等キーも使う。
- `400/409` は入力・競合、`401` はセッション、`403` は権限・上限、`429` は待機案内として分ける。

## 再構築の順序

1. 共通APIクライアント、セッション、エラー表示、ボタン状態。
2. 「今日」とマイ個体一覧。
3. 個体詳細とお世話記録。
4. ベビー群、餌在庫、QR。
5. 図鑑、相談、お世話フィード。
6. プロフィール、通知、繁殖募集ボード、外部連携。
7. 旧GUIとの機能比較、アクセシビリティ、モバイル検証。
8. 旧Ajax利用が0であることを確認して段階的に削除。

## 完了条件

- [ ] `GET /operations` にある利用者向け操作のうち、旧GUIで利用中の全操作へ新GUIから到達できる。
- [ ] 未ログインで図鑑・相談が読め、書込操作だけログインを要求する。
- [ ] 通常個体、ベビー、餌、QR、お世話記録の主要フローがスマートフォン片手で完了する。
- [ ] 読込中、空、通信失敗、権限不足、上限、競合の各状態がある。
- [ ] 破壊操作と外部連携には確認・監査可能な結果がある。
- [ ] `admin-ajax.php` を新GUIから呼んでいない。
- [ ] PHP/JavaScript構文、API契約、主要E2E、モバイル表示を検証済み。
