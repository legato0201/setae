# v1.0.251 リリースチェックリスト

このチェックリストは運用手順です。チェックされていない項目を実施済みと解釈しないでください。ローカルの実施結果はプラグインルートの `release-report-v1.0.251.md` を参照してください。

## 配布物

- ZIPのSHA-256を `.sha256` と照合する。
- ZIPの最上位が1つの `setae-core/` で、二重階層でないことを確認する。
- `setae-core.php` のheaderと `SETAE_VERSION` が1.0.251で一致することを確認する。
- 元のvendorを保持し、`.env`、秘密鍵、作業用ログ・実ユーザーデータ・macOS不要ファイルを含めない。
- v1.0.250 ZIP、DB、uploads、WordPress設定、Stripe設定をバックアップする。

## ステージング（実WordPressで未実施なら必須）

- 新設 `setae_product_events / setae_billing_events` の実DDL・一意索引を確認する。
- schema versionと計測開始optionがautoloadされないことを確認する。
- DBのユーザー単位named lock・書込み権限・トランザクション条件を確認する。
- 無料8匹・旧プレミアム・試用切れ・上限超過の各テストアカウントで、新規だけが制限され既存記録を操作できることを確認する。
- 旧個体・記録・ベビー群・写真・公開URL・QRが変わっていないことを確認する。
- 無料8匹の購入者が9匹目相当をQR受領し、手動枠8・受領枠外1になることを確認する。
- 引継ぎ専用登録から実メールを配送し、認証Cookie、303、トークンのない帰還URL、申請1件、所有者承認を通す。
- 無効トークン・再訪・一時障害で不正ログインや申請重複が起きないことを確認する。
- 試用の明示開始、選択保持、個体化、累計上限、期限切れ後の既存操作を確認する。

- テストモードのStarter Price、秘密鍵、Webhook署名secret、Customer Portalを設定する。
- `docs/monetization-foundation-v1.0.251.md` に記載したイベントを購読する。
- 表示価格が実Priceと一致しているか確認する。旧Priceは削除しない。
- Checkout成功・取消・二重クリック・通信切断再試行・Portalを実際に通す。
- Webhookの重複、順不同、一時失敗再送、支払い失敗、猶予、回復、予約解約、確定終了を確認する。
- 旧customerのみ・未知Price・複数subscriptionの警告を確認し、推測降格がないことを確認する。
- 本番へ切り替える場合はテストと本番のPrice/秘密鍵/署名secretを混在させない。

## 本番更新

- この作業のZIP生成は本番更新ではない。本番反映は別途承認・運用手順に従う。
- 更新前後でユーザー/個体/記録/群/QRの件数と代表データを照合する。
- 初回initのschema作成後、管理者のwarningとWebhook受信状態を確認する。
- 既存premiumを一括で新Starterへ変更しない。利用者の既存データを削除しない。
- 失敗したWebhookを再送し、inboxのfailedが回復することを確認する。

## 戻す場合

新しいテーブル・メタは残してプラグインを戻せますが、v1.0.250には新しい枠除外・試用・課金状態ポリシーがありません。単純に旧ZIPへ戻すとQR受領枠や支払い失敗の扱いが旧仕様に戻ります。課金Webhookを旧処理へ戻してよいかを先に判断し、必要ならCheckout導線を止めたうえでDBバックアップとStripeの実状態を照合してください。

ロールバック目的でイベント表、既存契約、個体、QRを削除・再発行してはいけません。外部Stripeの契約はDBバックアップの復元では巻き戻りません。
