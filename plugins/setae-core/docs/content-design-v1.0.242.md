# SETAE v1.0.242 Content Design

SETAEのUI文言は、対象、結果、次の行動が短い日本語で分かることを優先する。内部value、REST field、action、preference keyは変更せず、表示文言だけを`assets/app/content/terminology.js`と`messages.js`へ集約する。

## 基本原則

- 操作対象を明示する。「保存しました」ではなく「個体情報を更新しました」とする。
- 失敗理由または次の行動を示す。「エラーが発生しました」だけで終わらせない。
- 同じsemantic valueは画面にかかわらず同じ表記にする。
- 通常の見出し、状態、件数、操作名は日本語を使う。
- 学名、標本番号、内部コードは翻訳しない。
- 英語は主要コンテキストを示すeyebrowに限る。

## 許可する英語

主要画面の文脈を示す次のeyebrowは維持できる。

- `FIELD NOTEBOOK`
- `LABORATORY JOURNAL`
- `QUICK RECORD`
- `MY SETAE`
- `LIVING COLLECTION`
- `APPLICATION INFORMATION`

通常の表見出し、状態、件数、操作名には英語を使わない。学名は原綴り、個体番号は登録値を維持する。

## 禁止表現

対象が分からない次の表現を単独で使わない。

- 操作
- 処理
- 実行
- 更新しました
- 保存しました
- エラーが発生しました

必要な場合は「個体を登録しました」「入力内容を確認して、もう一度保存してください」のように対象と次の行動を補う。

## 件数表現

- 一般データと操作: `12件`
- 個体: `12匹`
- ベビー群: `3群`
- 写真: `8点`
- 在庫品目: 対象に応じて`8点`または`8件`
- 生存数: `78匹生存`

英語の`RECORDS`、`ITEMS`、`living`を件数表示へ残さない。

## 日時表現

- 日付は画面文脈に応じて`2026/08/27`または`8月27日`を使用する。
- 時刻を含む履歴は利用者のlocaleで表示する。
- 相対日は「6日前」「給餌予定を2日超過」のように対象を付ける。
- APIとFormDataの値は`YYYY-MM-DD`を維持する。

## 成功文言

- 個体を登録しました。
- 個体情報を更新しました。
- ベビー群を作成しました。
- 飼育容器を登録しました。
- 給餌を記録しました。
- 給餌を3件記録しました。
- SETAEの基本設定が完了しました。

## 失敗文言

- 個体を登録できませんでした。入力内容を確認して、もう一度保存してください。
- SETAEに接続できませんでした。通信環境をご確認のうえ、もう一度お試しください。
- この内容を表示する権限がありません。ログイン状態をご確認ください。
- 2件を同期しました。1件は再送が必要です。

失敗を成功Toastで上書きしない。field errorが分かる場合は該当field直下とForm上部のsummaryに示す。

## 削除文言

- 可逆なローカル変更は即時反映し、「元に戻す」を6秒表示する。
- アーカイブ、退居、共有解除は影響を説明する確認Dialogを使う。
- 個体とベビー群の完全削除は対象名を示し、確認文字の一致を必須にする。
- 記録削除では「最終給餌日・脱皮日などを再計算します」という影響説明を維持する。
- 復元APIがないサーバー削除には「元に戻す」を表示しない。

## オフライン文言

- オフラインです。操作はこの端末に保存し、再接続後に同期します。
- 操作をオフラインで保存しました。再接続後に同期します。
- 同期待ち 3件
- 3件を同期しています…
- 2件を同期しました。1件は再送が必要です。

同期待ち一覧では人間が理解できる操作名を主情報にし、`operation_id`と内部action codeは「詳細」に置く。オンラインかつqueueが空の場合は状態を表示しない。

## Contextual Empty State

`initial`はデータの作り方、`filtered`は条件の戻し方、`offline`は端末保存と同期方法、`error`は再試行方法、`permission`はログインまたは権限確認、`completed`は作業完了を伝える。色だけで区別せず、title、description、actionで意味を示す。
