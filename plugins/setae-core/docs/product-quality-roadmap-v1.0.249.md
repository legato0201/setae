# SETAE アプリ品質改善方針 / v1.0.249

作成日: 2026-08-28  
状態: 第1段階の実装と登録操作のローカル検証済み。本番には未適用。実機・実ユーザー検証と大量データ性能の課題は残る。

## 目指す品質

飼育中に短時間で「登録する・記録する・探す・確認する」を完了できるアプリにする。見た目の整合性だけでなく、誤操作の防止、入力の保持、失敗後の復帰までをデザインの対象とする。

既存の `design-system-v4.md` にある「Natural History Museum × Modern Research Database」を継続する。分類名と個体写真を主役にし、通常の操作は静かな配色、明確な文字の階層、整った余白と区切り線で整理する。独自のカード、色、装飾、アニメーションを画面ごとに追加しない。

## 調査で確認した問題と優先順位

| 優先度 | 問題 | 対応 |
|---|---|---|
| P0 | 登録フォームの `data-animal-id` を個体リンクと誤認し、入力中に背景の詳細画面へ遷移する | 個体を開く操作対象を明示。フォーム、モーダル、入力部品を対象外にする。空IDも入口で拒否する |
| P0 | 遅れて完了した個体取得が、その後に開いた画面へ結果やエラーを反映し得る | リクエストの世代、現在の画面、選択個体が一致するときだけ反映する |
| P1 | 登録時に必須と任意、種の選択方法、保存する内容が読み取りにくい | 必須表示、任意項目の説明、単位、登録・編集で異なる操作文言を整える |
| P1 | 種の選択で入力欄が置き換わり、キーボードの現在位置が失われる | 選択後は「変更」にフォーカスを渡す。エラー時は対象のラベルと入力欄を表示する |
| P1 | 検索語だけを消す操作と、保存ビューを含む絞り込み解除が混在する | 検索語だけを消すボタンを用意し、保存ビューと入力欄のフォーカスを保持する |
| P1 | 個体を取得できない画面に次の操作がない | 理由を断定せず、コレクションへ戻る操作を示す |

## 第1段階: 登録・検索・エラー復帰（今回）

### 実装した内容

- クリック、ダブルクリック、Enter、Spaceから個体を開く判定を共通化。入力欄、フォーム、ダイアログ、無効な操作要素を除外する。
- 日本語変換中のEnterと、別操作で処理済みのキーイベントを個体遷移に使わない。
- 登録モーダルを開くと、保留中のコレクション選択タイマーを解除する。
- 古い個体取得の成功、失敗、認証エラー処理が新しい画面を上書きしないようにする。
- 「個体識別」を必須の入口にし、状態・導入情報・写真・メモは任意と説明する。入力項目は削除しない。
- 種は候補からの選択と直接入力を区別する。種選択後のフォーカス、エラーと入力欄の関連付け、修正箇所へのスクロールを整える。
- 登録と編集で見出し、説明、保存ボタンを使い分ける。温度・湿度に単位を表示し、数値の0を空欄に変換しない。
- モバイルでも各セクションの説明を残す。本文だけをスクロールさせ、閉じる・キャンセル・保存の操作を維持する。
- 検索のクリアは現在の保存ビューを保ち、同じ検索語を再入力しても結果を更新する。空のときはクリアボタンを非表示にする。
- 検索結果の個体数を「匹」に統一し、個体取得失敗にはコレクションへの復帰操作を用意する。

### 変更しない契約

APIのURL、送信フィールド、DB構造、権限、既存個体の値は変更しない。入力フォーム、選択済み写真、保存中の二重送信防止、未保存変更の確認、既存の共有UI部品を維持する。

本番の個体データや図鑑データを、このリリース作業から書き換えない。

### 検証方法

従来のモーダル単体フィクスチャだけでは、アプリ全体のイベント委譲の問題を検出できなかった。そのため、実際の `app.js`、サービス、イベント処理、コントローラーを読み込むローカル回帰フィクスチャを追加する。API応答だけをローカルの合成データに置き換える。

新規登録と編集、キーボード入力、保存待機、保存失敗後の入力保持、再試行、古い通信の成功・失敗、検索クリアを検証する。既存のフォーム安全性・描画継続性のテストも再実行する。画面確認と自動試験の結果は `release-evidence/v1.0.249/` に保存する。

ローカルの合成APIによる保存成功を、本番WordPressへの保存確認とは扱わない。ブラウザーの表示幅変更も、実機のソフトウェアキーボードや日本語IMEの検証とは区別する。

## 第2段階: 日常操作に同じ品質基準を展開（未実装）

対象は Quick Record、個体編集、飼育容器、ベビー群。共通部品と画面ごとの責務を保ち、1つの操作フローずつ変更する。

| 実施順 | 改善内容 | 完了条件 |
|---|---|---|
| 1 | 操作の優先順位、対象個体、必須項目、単位、説明と下書き通知の位置を統一 | 各画面で主操作と保存対象が一意に分かる。新規・編集・処理中の文言が一致する。復元・破棄は必要な状態で示す |
| 2 | 任意項目の段階的な開示を検討・実装 | 入力済み、下書き復元、エラーのあるグループは開く。折り畳んでも値と写真を保持し、見えない項目へフォーカスしない |
| 3 | 読込中・空・失敗・成功の表示を統一 | エラーから再試行または戻る操作ができ、入力を失わない。空データと取得失敗を区別する |
| 4 | 320/390pxとデスクトップの情報密度を調整 | 横スクロールや操作ボタンの重なりがなく、長い個体名・学名・説明でも崩れない |
| 5 | 大量データでの検索・記録追加の待ち時間を改善 | 既存の性能テストで未達の項目を測定し、閾値を緩めずに改善・再試験する |

任意項目の折り畳みは今回入れない。下書き、写真、編集時の既存値、エラー時の自動展開を同時に保証してから導入する。

図鑑の飼育情報については、APIに保存済みの項目とアプリで表示する項目の対応も別途点検する。表示されていないデータを、UI改善だけで提供済みとは扱わない。

## 第3段階: 実機と利用者による仕上げ（未実施）

「個体登録 → 給餌記録 → 条件で検索 → QRを表示・印刷」という連続した操作で検証する。

- iOS Safari/PWA、Android Chrome/PWA、デスクトップで、キーボード表示中の保存操作、写真選択、戻る、回線不良、再試行を確認する。
- 日本語IME、キーボードのみの操作、スクリーンリーダー、ダークモード、動きを減らす設定を確認する。
- `usability-test-v1.0.244.md` の参加者条件と記録様式を引き継ぎ、経験者・初心者・初見の利用者で実施する。実施したビルド番号を別の記録に明記する。
- 完了率、所要時間、誤タップ、説明を求めた箇所を記録し、操作不能・データ損失・自力完了不能を優先して修正・再試験する。

現在、実ユーザー試験の実施を示す記録はない。開発者の目視や自動試験で代替したことにはしない。

## 各段階の共通完了条件

1. 主操作、操作対象、保存の成否が分かる。
2. 入力中に意図しない画面遷移がなく、失敗後も値・写真・フォーカスを保持できる。
3. キーボードとタッチの両方で操作でき、エラーのある入力欄とその説明へ到達できる。
4. 既存の共有部品、色・文字・余白のトークンを使い、機能固有のCSSは所有画面に置く。
5. 既存のAPI・データ・認証・QR印刷の契約を壊さない。
6. 自動試験、開発者の画面確認、実機、実ユーザー、本番確認を分けて報告する。

この文書は全画面の改善完了を意味しない。まず今回の入力不具合と主要な迷いを解消し、次の段階は上記の完了条件を満たす単位で進める。
